# Bilibili Evolved 多线程下载

中文 | [English](README.en.md)

一个 [Bilibili Evolved](https://github.com/the1812/Bilibili-Evolved) 插件，为「下载视频」添加两种多线程、多 CDN 节点的输出方式：

- **多线程（保存到文件夹）**：每个视频 / 音频流直接写入你选择的文件夹，不受内存限制，4K 和 2 GB 以上的文件也能下载。
- **多线程 + WASM 混流**：多线程下载音视频后，在浏览器中用 FFmpeg（WASM）合并为一个文件。

## 为什么需要它

「下载视频」自带的下载方式有两个问题：

1. **会把错误页保存成视频**
   - 部分 Mirror 节点（例如 `upos-sz-mirrorcosov.bilivideo.com`）对**不带 Range 的请求**返回 HTTP 567 和一个约 8.5 KB 的 HTML 错误页。
   - 「下载地址偏好」默认选 Mirror，而且只取第一个匹配的地址。实测海外网络下 4K 视频约 87% 的情况会选中这个节点。
   - StreamSaver 输出不检查响应状态，于是把这个错误页存成了视频文件。多点几次「开始」偶尔能成功，是因为 B 站偶尔把正常的节点排在了前面。
2. **单连接很慢**：节点常常限制单个连接的速度，实测一个连接只有约 0.3–0.55 MB/s。

本插件只发送带 Range 的请求，同时使用多个连接和多个节点，并会自动避开慢节点和故障节点。

## 功能

- **只接受正确的数据**：每个请求都带 Range，只有返回 206 且范围正确的响应才会写入文件。
- **使用所有地址**
  - B 站返回的主地址和备用地址都会用到。
  - 可选：把同一个签名地址换到最多 13 个其他节点上，以 Mirror 节点为主（[Bilibili-Evolved#3234](https://github.com/the1812/Bilibili-Evolved/issues/3234#issuecomment-1504764774) 记录了 Mirror 节点之间可以互换）。
  - 每个节点先测试，不可用的会被跳过。
- **多线程分块下载**
  - 默认 6 个连接、8 MB 一块，所有连接从同一个队列取块。
  - 下载过程中持续统计每个节点的速度，给快的节点多分块。
- **自动处理故障**
  - 10 秒收不到首字节、或 6 秒没有新数据的连接会被中止，剩余部分换节点续传。
  - 速度不到最快节点四分之一的连接会让出它的分块。
  - 失败的节点会暂停使用一段时间，返回 403 / 404 / 410 的节点不再使用。
  - 快结束时，空闲的连接会接手其他连接剩下的一半。
- **不受其他脚本影响**：通过一个空白 iframe 的 `fetch` 发送请求，页面或其他脚本（比如播放加速脚本）对 `window.fetch` 的改动不会影响下载。
- **可以取消**：进度提示里显示速度、连接数和节点数，点「取消」会停止下载并删除未完成的文件。
- **隐藏内置的 StreamSaver 输出**，避免误选到有问题的那个。如果想保留，把文件开头的 `HIDE_STREAMSAVER` 改为 `false`。

## 安装

1. 先安装 [Bilibili Evolved](https://github.com/the1812/Bilibili-Evolved)。
2. 打开 Evolved 的设置面板，进入「插件」页面。
3. 在「添加插件」处任选一种方式：
   - 把下面任一链接粘贴到输入框后添加：
     - `https://raw.githubusercontent.com/liweichen6/Bilibili-Evolved-MultiThread-Download/main/multi-thread-download.js`
     - `https://cdn.jsdelivr.net/gh/liweichen6/Bilibili-Evolved-MultiThread-Download@main/multi-thread-download.js`（GitHub 访问不畅时使用）
   - 或者下载 [`multi-thread-download.js`](multi-thread-download.js)，点「浏览」选择这个文件。
4. 刷新 B 站页面。

## 使用

1. 打开「下载视频」，像往常一样选择画质等选项。
2. 在「输出方式」中选择「多线程（保存到文件夹）」或「多线程 + WASM 混流」。
3. 点「开始」。

**保存到文件夹**

- 第一次会弹出文件夹选择框，Chrome 会询问是否允许网站写入这个文件夹。
- 如果从点「开始」到弹出选择框之间隔得太久，浏览器会拒绝直接打开它，这时会出现「点击这里选择保存文件夹」的提示，点一下即可。
- 文件名与内置下载相同，视频和音频分别保存。同名文件已存在时，会自动加上「(1)」这样的编号。
- 只有 Chrome / Edge 支持直接写入文件夹。其他浏览器会先把文件下载到内存，再作为普通下载保存。

**WASM 混流**

- 第一次使用需要加载约 30 MB 的 FFmpeg 文件。这些文件与 Evolved 自带的「WASM 混流输出」共用同一个缓存，用过那个插件的话就不用再下载。
- 由于浏览器限制，只能合并 2 GB 以内的音视频，更大的请用「保存到文件夹」。

## 设置

每种输出方式下方都有设置项：

| 设置 | 默认 | 说明 |
|---|---|---|
| 连接数 | 6 | 同时下载的连接数：2 / 4 / 6 / 8 / 12 / 16 |
| 分块大小 | 8 MB | 每个分块的大小：2 / 4 / 8 / 16 MB。网络延迟高时建议用较大的分块 |
| 扩展 CDN 节点 | 开 | 除了 B 站返回的地址，也尝试其他节点 |
| 输出格式 | auto | 仅 WASM 混流：auto / mp4 / matroska。指定 MP4 时，无损音轨会从 FLAC 重新编码为 ALAC |
| 写入元数据 | 关 | 仅 WASM 混流，需要启用「保存视频元数据」组件 |
| 附加封面 | 关 | 仅 WASM 混流，需要启用「查看封面」组件 |

## 实测

测试环境：海外网络，Chrome 156，Tampermonkey 5.5.1，Bilibili Evolved 2.11.5，视频 BV1tZxj6ZEVa。

| 测试 | 结果 |
|---|---|
| 单个普通连接下载 720P 视频（56 MB） | 237 秒 |
| 本插件保存到文件夹，720P 视频 + 音频（共 68 MB） | 21.9 秒，视频与单连接下载的结果逐字节一致 |
| 本插件 WASM 混流，同一视频 | 12.3 秒，得到 68.6 MB 的 MP4 |
| 本插件下载 1080P | 约 10.6 MB/s，6 个连接分布在 6 个节点上 |

速度很大程度上取决于网络和当时的节点状况，以上数据仅供参考。

## 已知限制

- 「扩展 CDN 节点」使用的节点列表来自实际观察，不是 B 站公开的规则。不接受签名的节点会在测试时被跳过，但 B 站随时可能改变规则。
- 只能使用 B 站返回的地址，以及由这些地址换出的节点。如果所有地址都失效，请重新点「开始」获取新地址。
- 以下情况尚未充分测试：2 GB 以上的文件、写入元数据和附加封面、批量下载、只有 FLV 格式的旧视频、Chrome 以外的浏览器。遇到问题欢迎提 Issue。
